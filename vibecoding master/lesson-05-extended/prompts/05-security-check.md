# Security-check после интеграций

Финальный аудит после добавления AI, админки, REST API, Telegram-алертов, email. Каждая новая интеграция = новый вектор атаки. (Безопасность файлов проверяется в Уроке 4, здесь не дублируется.)

## Чек-лист по векторам

### AI (Шаг 1)
- [ ] `ANTHROPIC_API_KEY` / `OPENROUTER_API_KEY` только в `.env`, не во frontend bundle
- [ ] Все AI-вызовы идут через бэкенд (Next.js API), не из браузера
- [ ] Rate limit на `/api/ai/*` — например 10 req/min/user
- [ ] Лимит расхода на пользователя (поле `aiUsage`)
- [ ] **Prompt injection защита:** пользовательский ввод санитайзится перед вставкой в системный промт
- [ ] Логирование AI-запросов в БД для audit

### Админка (Шаг 2)
- [ ] Маршрут `/admin/*` защищён middleware (role=admin)
- [ ] Все mutations пишутся в `ActivityLog`
- [ ] Список admin-пользователей минимизирован
- [ ] Нельзя удалить самого себя

### REST API (Шаг 3)
- [ ] API key хранятся как **хэш** в БД (не plaintext)
- [ ] Scope-based авторизация (read/write по типам ресурсов)
- [ ] Rate limit per key (100/min)
- [ ] Logging всех вызовов + alert на подозрительную активность
- [ ] HTTPS обязателен, отклоняем HTTP запросы
- [ ] Документация публична, ключи приватны

### Telegram-оповещения владельцу (Шаг 4)
- [ ] `TELEGRAM_BOT_TOKEN` только в `.env`, не в коде/репозитории (`chat_id` — не секрет)
- [ ] Бот шлёт строго по белому списку `TELEGRAM_ALERT_CHAT_IDS` — не отвечает всем, кто ему написал
- [ ] Только исходящие сообщения — нет webhook, приёма команд, привязки аккаунтов (поверхность атаки минимальна)
- [ ] В текст алертов не попадают пароли, токены, персональные данные пользователей

### Email (письма из Урока 4)
- [ ] SMTP / API ключи в `.env`
- [ ] Rate limit отправок: 5/час/пользователь
- [ ] Подтверждение email перед важными нотификациями
- [ ] Unsubscribe в маркетинговых письмах (закон)
- [ ] Anti-spoofing: SPF + DKIM + DMARC настроены для домена

### In-app уведомления (центр из Урока 4)
- [ ] Уведомления изолированы по `userId` (нельзя прочитать чужие)
- [ ] Real-time каналы аутентифицированы
- [ ] Подписка на каналы только своих уведомлений

## Прогон автоматики

```
Запусти свой аудит безопасности (рецепт собран в Уроке 3): на Claude Code — скилл /security-check, на Codex/Cursor — «прочитай prompts/security-check.md и выполни». Сделай полный аудит OWASP Top 10 + чек-лист выше (новые векторы Урока 5: AI prompt injection, REST API auth, rate limit на admin, секреты Telegram-бота в env). Сохрани отчёт в ../../product/docs/audits/security-check-lesson-05-<date>.md.

Если нашёл 🔴-проблемы — список + план починки. Если ⚠️ — приоритет 2, можно отложить. ✅ — всё хорошо.
```

## После аудита

1. Покажи пользователю найденные проблемы (🔴 + ⚠️)

2. По 🔴 проблемам — план починки, выполни сразу

3. По ⚠️ — добавь в `../../product/docs/security-todo.md` для разбора позже

4. ADR в `../../product/docs/memory/decisions/`: ADR-X-security-baseline-after-lesson-5

## Финальная проверка

После починки 🔴 — прогон ещё раз. Чисто? Идём дальше.
