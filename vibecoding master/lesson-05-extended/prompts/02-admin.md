# Админка (`/admin`)

Цель: отдельный раздел `/admin` для role=admin — управление контентом/данными, страница со всеми действиями (логи) и обзор с метриками (отчёты).

> **Сначала разбор, потом код.** Админка — сложный кусок (роли, серверные проверки доступа, лог действий, метрики). Прежде чем писать код, разбери фичу со мной: какие сущности и метрики из `spec.md` нужны, кто что видит, как считаем числа. В Claude Code это делает скилл `/new-feature` (интервью → бриф → реализация); если скилла нет (Codex/Cursor/другой AI) — задай мне уточняющие вопросы по `spec.md` и покажи план, и только после согласования реализуй.

## Шаг 1 — Роль admin

Если в `spec.md` нет роли admin — добавь:
- В `User` модели поле `role: 'user' | 'admin'` (default `user`).
- Первого admin создаём руками (через seed или SQL) — себе.

## Шаг 2 — Защита маршрута `/admin`

Роль проверяется **на сервере** (в layout/middleware и в каждом admin-endpoint), а не только в UI — иначе проверку можно обойти.

```ts
// ../../product/src/app/admin/layout.tsx (или middleware)
import { getSession } from '@/lib/auth'

export default async function AdminLayout({ children }) {
  const session = await getSession()
  if (!session?.user || session.user.role !== 'admin') redirect('/')
  return <AdminShell>{children}</AdminShell>
}
```

**Обвязка админки — в этом layout, не в страницах (тот же принцип, что в Уроке 2).** `AdminShell` (меню/сайдбар админки) живёт в `admin/layout.tsx` и оборачивает все страницы `/admin/*`. Layout переживает переходы между разделами админки и не перемонтируется — при переключении «Обзор → Сущности → Логи» меню не перезагружается, меняется только контент. Поэтому навигацию по разделам делай через `<Link href="/admin/...">` из `next/link` (мягкие переходы + префетч), а не `<a href>`; активный раздел подсвечивай через `usePathname()`. Не дублируй меню админки внутри страниц разделов.

## Шаг 3 — Структура админки (по умолчанию три раздела)

`/admin` с навигацией по разделам:

1. **Обзор (`/admin`)** — дашборд с метриками: сколько пользователей, сколько записей основной сущности, сколько за последние 7 дней, и т.п. (см. Шаг 6).
2. **Контент/данные** — по табу на сущность из `spec.md` (Users, Orders, Posts…): таблица со списком, просмотр, правка, удаление.
3. **Логи (`/admin/logs`)** — все действия в системе: кто, когда, что сделал (см. Шаг 5).

## Шаг 4 — Управление контентом (переиспользуемая таблица)

Сделай `../../product/src/shared/ui/admin-table.tsx`, принимающий `columns`, `data`, `actions` (view / edit / delete), `filters`, `pagination`. Используй на каждом табе сущности — чтобы добавить новый раздел, достаточно описать колонки. Все действия идут через admin-endpoints с серверной проверкой роли и пишутся в лог (Шаг 5).

## Шаг 5 — Страница логов (все действия)

Каждое действие (создал/изменил/удалил, вход админа, выдача API-ключа) пишем в `ActivityLog`, и показываем на `/admin/logs` с фильтрами (по пользователю, типу действия, дате):

```prisma
model ActivityLog {
  id        String   @id @default(uuid())
  userId    String   // кто сделал
  action    String   // 'user.update' / 'order.delete' / 'apikey.create'
  target    String?  // 'user:abc' / 'order:xyz'
  metadata  Json?    // что именно изменилось
  createdAt DateTime @default(now())
  @@index([createdAt])
  @@index([userId])
}
```

Заведи хелпер `logAction(userId, action, target?, metadata?)` и зови его из всех admin-мутаций. На `/admin/logs` — та же `AdminTable`, отсортировано по `createdAt desc`.

## Шаг 6 — Обзор с отчётами (метрики)

На `/admin` — карточки с ключевыми числами по реальным запросам к базе (не выдуманные). Минимум:
- всего пользователей / новых за 7 дней;
- всего записей основной сущности / новых за 7 дней;
- 2-3 продуктовые метрики из `spec.md` (например: оплат, активных подписок, заявок в статусе «новая»).

Считаем в коде/БД (`prisma.count`, `groupBy`), не на глаз. Если в `spec.md` есть свои показатели — добавь их. По желанию — простой график динамики за 30 дней.

```ts
const [users, usersWeek, orders] = await Promise.all([
  db.user.count(),
  db.user.count({ where: { createdAt: { gte: weekAgo } } }),
  db.order.count(),
])
```
