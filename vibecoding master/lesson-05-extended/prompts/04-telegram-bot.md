# Telegram-оповещения владельцу

> **Сначала разбор, потом код.** Прежде чем писать код, разбери фичу со мной: о каких событиях из `spec.md` я хочу узнавать и кому из людей должны приходить алерты (белый список). В Claude Code это делает скилл `/new-feature` (интервью → бриф → реализация); если скилла нет (Codex/Cursor/другой AI) — задай мне уточняющие вопросы и покажи план, и только после согласования реализуй.

## Когда делать

Если хотите получать в личный Telegram сообщения от сервиса — «упал», «новая заявка», «ошибка на сервере». Это **не** пользовательская фича: пользователи продукта бота не видят и не используют. Канал односторонний: сервис → вы.

## Что это и чего тут НЕТ

Это только **исходящие** сообщения через Telegram Bot API. Поэтому НЕ нужно:
- webhook и приём сообщений от пользователей,
- библиотека grammy и handler'ы команд,
- поле `telegramId` у `User` и привязка аккаунтов,
- ничего общего с моделью данных продукта.

Нужны всего две вещи: токен бота и список `chat_id`, кому слать. Свой `chat_id` пользователю знать НЕ нужно — его подтянет AI автоматически (см. Шаг 2). Дальше — одна функция, которая шлёт текст всем разрешённым получателям.

```
Код сервиса → fetch(Telegram Bot API sendMessage, для каждого chat_id из белого списка) → сообщение в личку
```

**Белый список — ключевой момент.** Бот шлёт сообщения ТОЛЬКО тем `chat_id`, что записаны в env (`TELEGRAM_ALERT_CHAT_IDS`). Если боту напишет посторонний человек — он просто попадёт в `getUpdates`, но бот ему ничего не отправляет и он никогда не видит ваши алерты. Чтобы добавить нового получателя, его `chat_id` надо явно внести в список (Шаг 2 ниже).

## Шаг 1 — Создать бота

Попроси пользователя:

1. Открыть `@BotFather` в Telegram
2. Отправить `/newbot` → задать имя и username
3. Скопировать выданный токен (вид `123456:ABC-DEF1234ghIkl...`)

## Шаг 2 — chat_id определяем автоматически (пользователь его не ищет)

Свой `chat_id` обычный человек не знает и искать вручную не должен. Поэтому единственное, что делает пользователь — **пишет боту `/start`** (без этого Telegram не даст боту написать первым). Дальше `chat_id` находишь ты сам и сам вписываешь в env.

1. Скажи пользователю: «Найди своего бота по username и отправь ему `/start` (или любое сообщение)».
2. Создай одноразовый скрипт-помощник, который читает токен из env (ты его значение не видишь — оно подставляется из файла) и вызывает `getUpdates`:

```js
// ../../product/scripts/telegram-discover-chatid.mjs
// запуск (cwd=урок): cd ../../product && node --env-file=.env.local scripts/telegram-discover-chatid.mjs
const token = process.env.TELEGRAM_BOT_TOKEN
if (!token) { console.error('Нет TELEGRAM_BOT_TOKEN в .env.local'); process.exit(1) }

const res = await fetch(`https://api.telegram.org/bot${token}/getUpdates`)
const data = await res.json()

const chats = new Map()
for (const u of data.result ?? []) {
  const c = (u.message ?? u.edited_message ?? u.channel_post)?.chat
  if (!c) continue
  const who = [c.first_name, c.last_name, c.username && '@' + c.username].filter(Boolean).join(' ')
  chats.set(c.id, who || c.title || '—')
}

if (chats.size === 0) console.log('Боту ещё никто не писал. Отправь боту /start и запусти снова.')
else { console.log('Кто написал боту (chat_id → кто):'); for (const [id, who] of chats) console.log(`  ${id}\t${who}`) }
```

3. Запусти скрипт, прочитай вывод (это просто числа — `chat_id` не секрет), определи `chat_id` пользователя и **сам впиши его** в `TELEGRAM_ALERT_CHAT_IDS` в `.env.local` и `.env.production`. Пользователю ничего копировать не нужно.
4. После того как все нужные `chat_id` записаны — удали скрипт `../../product/scripts/telegram-discover-chatid.mjs` (одноразовый).

## Шаг 3 — Env-переменные

Токен — секрет, его вписывает пользователь сам; `chat_id` — не секрет, его впишешь ты сам по итогам Шага 2. Создай (или дополни) `.env.local` и `.env.production`:

- `TELEGRAM_BOT_TOKEN=впиши-токен-от-BotFather` — пользователь вписывает в файл сам (НЕ в чат, НЕ в терминал).
- `TELEGRAM_ALERT_CHAT_IDS=` — **белый список получателей через запятую**, заполняешь его ты сам по итогам Шага 2 (пользователь сюда ничего не вписывает — id берутся из `getUpdates`). Например: `TELEGRAM_ALERT_CHAT_IDS=123456789` или `123456789,987654321`.

Скажи: «Открой `.env.local`, впиши токен после `TELEGRAM_BOT_TOKEN=`, сохрани». Токен ты не видишь, к Telegram API обращаешься, читая его из `process.env`. Файлы `.env.*` уже в `.gitignore`.

### Добавить ещё одного получателя

Когда позже нужно, чтобы алерты приходили ещё кому-то (партнёру, второму админу):

1. Этот человек открывает бота и пишет ему `/start`.
2. Ты снова прогоняешь `telegram-discover-chatid.mjs` — в выводе появляется его `chat_id` с именем.
3. Ты дописываешь его id в `TELEGRAM_ALERT_CHAT_IDS` через запятую (в `.env.local` и `.env.production`) и перезапускаешь приложение/контейнер.

Все, кого нет в списке, бот просто игнорирует: написал боту посторонний — он попал в `getUpdates`, но алертов не получает.

## Шаг 4 — Функция отправки

Никаких внешних библиотек — обычный `fetch`:

```ts
// ../../product/src/lib/telegram-alert.ts
export async function sendTelegramAlert(text: string) {
  const token = process.env.TELEGRAM_BOT_TOKEN
  const chatIds = (process.env.TELEGRAM_ALERT_CHAT_IDS ?? '')
    .split(',').map((s) => s.trim()).filter(Boolean) // белый список получателей
  if (!token || chatIds.length === 0) return // не настроено — молча выходим

  // шлём каждому разрешённому chat_id; кого нет в списке — не получит ничего
  await Promise.all(
    chatIds.map((chatId) =>
      fetch(`https://api.telegram.org/bot${token}/sendMessage`, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ chat_id: chatId, text, parse_mode: 'HTML' }),
      }).catch(() => {}) // алерт не должен ронять основной поток — ошибку отправки глотаем
    )
  )
}
```

## Шаг 5 — Куда подключить

Зови `sendTelegramAlert` там, где хочешь узнать о событии:

- **Глобальный обработчик ошибок** — при необработанной ошибке на сервере шлёт тебе текст ошибки (без чувствительных данных пользователя).
- **Важные бизнес-события из `spec.md`** (если есть) — «новый заказ», «первая оплата» и т.п.
- **Uptime-мониторинг** (этот же шаг, дальше — `04b-uptime-monitoring.md`) — отдельный cron шлёт алерт напрямую через тот же токен/chat_id, не через приложение (если упало само приложение, его код уже не выполнится).

Не спамь: алерты — про важное и редкое, а не про каждый запрос.

## Безопасность

- **Токен** — секрет: только в env (права 600), не в коде и не в репозитории. `chat_id` секретом не является (это просто адрес чата), его можно вписывать в env самому.
- **Белый список — это и есть защита.** Бот шлёт только тем, кто в `TELEGRAM_ALERT_CHAT_IDS`. Никаких «отвечать всем, кто написал» — иначе любой, кто нашёл бота, начнёт получать ваши внутренние алерты. Получатель добавляется только явно (Шаг 2).
- В текст алерта не клади пароли, токены, персональные данные пользователей — сообщение уходит в обычный чат.

## После реализации

1. Вызови тестовый `sendTelegramAlert('тест')` — сообщение приходит всем из белого списка.
2. Проверь изоляцию: с другого аккаунта напиши боту `/start` — этот человек НЕ должен получать алерты (его нет в `TELEGRAM_ALERT_CHAT_IDS`).
3. Убедись, что одноразовый `../../product/scripts/telegram-discover-chatid.mjs` удалён.
4. Покажи, что пользователи продукта бота никак не касаются (нет webhook, нет команд, нет привязки).
5. ADR в `../../product/docs/memory/decisions/`: Telegram как канал оповещений владельцу (только исходящие, белый список chat_id), почему без webhook/grammy.
