# Настройка AI — permissions и AGENTS.md как разводящий хаб

> **Universal AI prompt.** Этот файл написан так, чтобы любой AI (Claude Code, OpenAI Codex, Cursor, Aider) мог прочитать и выполнить. См. блок «Определи окружение» ниже — он задаёт пути для остальных шагов.

## Шаг 0 — Определи окружение

Сначала пойми, какой ты AI — от этого зависят пути. Запомни на весь промт. Папки инструментов не смешиваются: используется либо набор Claude Code, либо набор Codex/Cursor, но не оба сразу.

**Если ты Claude Code** (есть sub-агенты и slash-команды `/...`):
- Правила (`AGENTS.md`) и промты-рецепты (`prompts/`) — **внутри** `../../product/`. Это source, он едет с репо: кто клонирует `product/`, сразу получает правила и рецепты.
- Обёртки, которые должны гарантированно срабатывать у тебя — **скиллы и хуки** — в `.claude/` в **корне воркспейса** (рядом с `lessons/` и `product/`). Claude грузит конфиг из открытой папки (обычно это весь воркспейс) и внутрь `product/` сам не заглядывает. Скиллы тонкие — внутри ссылка на рецепт из `product/prompts/`. Полная схема — в разделе «Каноническая структура» ниже.
- Правила проекта — `../../product/AGENTS.md`, плюс симлинк `../../product/CLAUDE.md` → `AGENTS.md` (Claude исторически ищет `CLAUDE.md`), а в КОРНЕ — `CLAUDE.md` с `@product/AGENTS.md`, чтобы правила грузились гарантированно при открытом воркспейсе.
- Глобальные настройки — `~/.claude/settings.json`. Память проекта — в `../../product/docs/memory/` (нейтрально, кросс-тул, едет с репо).

**Если ты Codex, Cursor или другой AI** (slash-команд нет):
- Папку `../../.claude/` НЕ создаёшь — она тебе не нужна.
- Правила проекта — `../../product/AGENTS.md` в корне (ты читаешь его сам).
- Промты курса — в `prompts/`, зовёшь по пути («прочитай `prompts/<имя>.md` и выполни»).
- Память проекта — в `../../product/docs/memory/`.
- Разрешения (permissions) — в своём глобальном конфиге: Codex → `~/.codex/config.json`, Cursor → настройки IDE.

Дальше пути даю явно для каждого случая.

## Как это работает — читать до запуска

Когда ты (AI) отправляешь промт или начинаешь сессию, перед ответом ты автоматически читаешь файл правил проекта из корня (`AGENTS.md`). Это значит: всё что написано в `AGENTS.md` — AI знает при каждом промте, без напоминаний.

Поэтому `AGENTS.md` — это не документация для людей, это **инструкция для AI которая всегда в памяти**. Всё что туда попадает, работает постоянно и автоматически.

На этом этапе мы используем `AGENTS.md` для одной вещи — **железных правил** проекта. Это то, что нельзя нарушать никогда. Вписываем их один раз, и AI следует им в каждой сессии:
- spec.md всегда актуален — любое изменение поведения сначала в спеке
- DESIGN.md → UIKit → Экран — любое визуальное изменение сначала в дизайн-системе

Контекст продукта (что за продукт, для кого) сюда **не вписываем** — он живёт в `../../product/docs/spec.md → раздел Продукт` и заполняется на следующем промте `02-product-context.md`. В `AGENTS.md` ставим только указатель: «см. spec.md».

**Permissions** — отдельная настройка: какие действия AI может делать сам, не спрашивая разрешения. Читать файлы, запускать `npm run dev`, искать через grep — это рутина, постоянные подтверждения только замедляют. А вот `git push` или удаление файлов — должен спрашивать. Настраиваем один раз.

## Что делаем

1. Настроить разрешения (permissions) в своём конфиге: Claude Code — `~/.claude/settings.json`, Codex — `~/.codex/config.json`, Cursor — настройки IDE. См. блок «Permissions» ниже.

2. Создать `../../product/AGENTS.md` — индекс правил проекта (компактный хаб, не свалка).

3. Только Claude Code → собрать каноническую структуру: правила и рецепты — в `../../product/` (симлинк `../../product/CLAUDE.md → AGENTS.md`), а в корне воркспейса — `CLAUDE.md` с `@product/AGENTS.md` и папка `.claude/` под будущие скиллы/хуки-обёртки. См. раздел «Каноническая структура» ниже. Codex/Cursor читают `../../product/AGENTS.md` сами.

4. Только Claude Code, по желанию — `../../.claude/settings.local.json` (в корне воркспейса) с локальными правилами проекта.

## Permissions — чтобы AI не спрашивал разрешение на каждое действие

По умолчанию AI переспрашивает почти на каждое действие: «можно прочитать файл?», «можно запустить?». Для безопасности это полезно, но на курсе сильно тормозит. Один раз настроим разрешения: рутину AI делает сам, а на опасное и необратимое по-прежнему спрашивает.

Вручную лезть в файл настроек и писать конфиг не нужно — попросите AI сделать это за вас. Введите в ваш AI:

```
Настрой свои разрешения так, чтобы не спрашивать у меня подтверждение на рутинные безопасные действия, но всё опасное оставить под подтверждением.

ВАЖНО: разреши не только правку файлов, но и САМО выполнение терминальных команд из списка ниже — без подтверждения. Обязательно включи смену директории (`cd`) и составные команды (`cd <папка> && <команда>`): на них автозапуск спотыкается чаще всего, и если их не разрешить, AI будет переспрашивать почти на каждой команде, хотя «редактирование файлов» уже разрешено.

Делай сам, без вопросов:
- читать, искать и редактировать файлы внутри проекта;
- выполнять терминальные команды из этого списка, включая `cd` и составные `cd … && …`;
- навигация и файлы: ls, cat, head, tail, grep, find, mkdir, touch, cp, mv;
- git только для чтения и подготовки: status, log, diff, branch, show, add, fetch, pull;
- пакеты и запуск: npm / pnpm / yarn / bun (install и run), npx, node;
- dev-сервер, тесты, сборка; docker ps и логи; открытие localhost.

Если я работаю на WINDOWS (PowerShell / cmd / Git Bash) — добавь те же разрешения для эквивалентов моей оболочки, чтобы автозапуск работал и у меня, а не только в bash:
- смена директории и составные команды: `cd`, `Set-Location`, цепочки через `;` и `&&`;
- навигация/файлы: dir, `Get-ChildItem` (ls); type, `Get-Content` (cat); findstr, `Select-String` (grep); where, `Where-Object`; md / `New-Item` (mkdir); copy / `Copy-Item` (cp); move / `Move-Item` (mv);
- те же npm / pnpm / yarn / bun / npx / node, git-команды чтения, dev-сервер и тесты.
Определи мою ОС/оболочку (спроси меня, если не уверен) и пропиши паттерны под неё.

Всегда спрашивай подтверждение:
- git commit, git push, git reset, git checkout, git restore (могут затереть мои правки);
- удаление файлов и папок во всех вариантах оболочки (rm / del / rmdir / rd / Remove-Item), смена прав (chmod / icacls / attrib), публикация пакетов, миграции прод-базы, отправка писем.

Никогда не выполняй без моей явной команды (разрушительное по корню или домашней папке) — во ВСЕХ вариантах оболочки:
- Git Bash: `rm -rf /`, `rm -rf ~`, `sudo rm`;
- PowerShell: `Remove-Item -Recurse -Force` по корню/домашней (и его алиасы rm/del/rmdir);
- cmd: `rd /s /q` и `rmdir /s /q` по корню/домашней, `del /f /s /q` по корню, `format`, `diskpart`;
- git push --force в main, git reset --hard origin/main; запуск разрушительного с повышением прав (sudo / runas / «от администратора»).

Пропиши это в файле настроек своего инструмента (ты знаешь, где он: Claude Code — ~/.claude/settings.json, Codex — ~/.codex/config.json, Cursor — настройки IDE). Затем ПРОВЕРЬ, что автозапуск реально работает: выполни простую команду (`cd <папка проекта> && ls`, на Windows — `cd <папка> ; dir`) — она должна пройти БЕЗ запроса подтверждения. Если всё ещё спрашивает — допиши недостающий паттерн и проверь снова. Покажи, что получилось в конфиге, и результат проверки.
```

AI сам знает формат настроек своего инструмента и пропишет нужное — вам формат знать не надо.

**Что останется под подтверждением — и это правильно:** коммиты и пуши в git, удаление файлов, всё необратимое и всё с эффектом вовне. Так вы всегда видите, что AI собирается отправить наружу или стереть, прежде чем это случится.

## AGENTS.md — формат (универсальный для всех AI)

`AGENTS.md` это **разводящий хаб**, не свалка. Он подгружается в контекст AI перед каждым промтом, поэтому должен быть компактным (≤200 строк). Принцип: индекс по триггерам → файл правил.

Структура:

```markdown
# AGENTS.md

## Контекст продукта
См. `../../product/docs/spec.md → ## Продукт` (заполняется на следующем промте `02-product-context.md`). Здесь не дублируем — один источник правды.

## Железные правила — всегда, без исключений

### 1. spec.md всегда актуален
Любое изменение поведения продукта (логика, состояния, действия, данные, доступы) →
сначала обновить `../../product/docs/spec.md`, потом менять код.
Коммит без обновления spec.md считается незавершённым.

### 2. DESIGN.md → UIKit → Экран
Любое визуальное изменение идёт строго в одном направлении:
`../../product/docs/DESIGN.md` → `../../product/src/shared/ui/` → страницы / виджеты / фичи.
Нужен новый токен (цвет, шрифт, отступ) → сначала в DESIGN.md.
Нужен новый вариант компонента → сначала в `shared/ui/`, потом использовать.
Хардкод хексов, пикселей, inline-стилей на странице — запрещён.

### 3. Безопасность и дисциплина — всегда
- **Секреты** (ключи, токены, пароли) — только в `.env` или переменных окружения, **никогда** в коде, файлах проекта или чате. Увидел секрет где-либо (в коде, диффе, команде) — остановись, предупреди, предложи перенести в `.env`.
- **Делать до конца, не срезать.** Если в шаге есть список/набор (компоненты, экраны, разделы) — выполняй **весь**, не «самое важное на этом хватит». Не сокращай и не оставляй заглушки молча: чего не сделал — назови явно и почему.
- **Без оценок времени** в часах/днях — объём словами: «мелкая правка», «отдельная задача», «отдельный проект», «~N файлов».
- Перед shell-командой коротко поясняй, что и зачем она делает.

## Правила (читать по триггеру)

| Когда | Файл |
|---|---|
| Создаёшь файл / решаешь куда положить код | `../../product/docs/rules/project-structure.md` |
| Перед коммитом (появится на этапе деплоя) | `../../product/docs/rules/commits.md` |
| Деплой / инфра | `../../product/docs/memory/infrastructure.md` |
| ... | ... |

## Активная работа
См. `../../product/docs/memory/state.md` (что сейчас делаем, какие шаги пройдены).

## История решений
См. `../../product/docs/memory/INDEX.md` (ADR, findings, sessions).
```

Файлы из таблицы создавать пока **не нужно** — они появятся на следующих этапах (memory подключается на этапе защиты от регрессий, Урок 6). Железные правила вшиты сразу и действуют с первого дня.

> **Git пока не подключаем.** На этапе продукта и дизайна работаем локально — **не коммитим и не пушим** (даже если AI предлагает). Сам git, GitHub и правило коммитов (`commits.md`) появляются на этапе деплоя (Урок 3): как только git подключён, коммит после каждого завершённого шага включается автоматически. До этого — никаких коммитов.

### Каноническая структура: рецепты и правила в `product/`, обёртки в корне

Идея простая. То, что должно ехать с проектом к команде — **правила** (`AGENTS.md`) и **промты-рецепты** (`prompts/`) — лежит внутри `product/` (это отдельный git-репозиторий, его клонирует команда). А **обёртки**, которые должны гарантированно срабатывать у тебя — скиллы и хуки — лежат в `.claude/` в **корне воркспейса** (Claude грузит конфиг из открытой папки, а это обычно весь воркспейс, и внутрь `product/` сам не заглядывает). Обёртки тонкие: внутри только ссылка на реальный рецепт/правило в `product/`. Так у тебя они гарантированно в наборе, а команда внутри `product/` пользуется теми же рецептами напрямую.

| Что | Где | Почему там |
|---|---|---|
| Правила `AGENTS.md` (+ `CLAUDE.md` → `AGENTS.md`) | `product/` | едут с репо; команда сразу получает правила |
| Промты-рецепты `prompts/*.md` | `product/prompts/` | едут с репо; команда зовёт по пути |
| Скиллы `.claude/skills/*/SKILL.md` (тонкие обёртки) | корень воркспейса | гарантированно в наборе; внутри — ссылка на `product/prompts/<имя>.md` |
| Хуки `.claude/hooks/*.sh` | корень воркспейса | гарантированно срабатывают |
| `.claude/settings.json` (permissions + регистрация хуков) | корень воркспейса | грузится из открытой папки |
| `CLAUDE.md` = `@product/AGENTS.md` | корень воркспейса | импортирует правила продукта — они в контексте с первого сообщения, а не лениво |

**Если ты Claude Code** — на этом шаге собери базу (через Bash-tool, из корня воркспейса):

```bash
# Правила — внутри продукта (source)
( cd product && [ -e CLAUDE.md ] || ln -sf AGENTS.md CLAUDE.md )   # Claude ищет CLAUDE.md
# В корне — указатель на правила продукта: импорт = гарантированная загрузка
printf '@product/AGENTS.md\n' > CLAUDE.md
mkdir -p .claude   # сюда позже лягут скиллы и хуки (Уроки 3+); settings.json — на шаге Permissions ниже
```

Скиллы (`/security-check` и др.) и хуки появятся в `.claude/` корня на следующих уроках — каждый скилл будет тонкой обёрткой, зовущей свой рецепт из `product/prompts/`. Реальные рецепты и правила — в `product/`, поэтому команда, клонируя `product/`, получает всю суть и зовёт промты по пути.

**Если ты Codex / Cursor** — `.claude/` и скиллов нет: читаешь `product/AGENTS.md` напрямую и зовёшь промты по пути `product/prompts/<имя>.md`. Чтобы при открытом воркспейсе Codex тоже видел правила, сделай в корне ярлык: `ln -sf product/AGENTS.md AGENTS.md`.

## Локальный settings проекта (опционально)

Если для конкретного продукта нужны permissions отличные от глобальных:

- **Claude Code:** создай `../../.claude/settings.local.json` (в корне воркспейса) и переопределяй
- **Codex:** отдельного проектного файла настроек нет — права задаются в глобальном `~/.codex/config.json`
- **Cursor:** проектный `../../.cursor/settings.json`

Пример (Claude формат):

```json
{
  "permissions": {
    "allow": [
      "Bash(docker compose:*)",
      "Bash(prisma:*)"
    ]
  }
}
```

## После выполнения покажи

1. Содержимое настроенного конфига с разрешениями (`~/.claude/settings.json`, `~/.codex/config.json` или скриншот настроек Cursor).

2. Созданный `../../product/AGENTS.md` целиком.

3. Если ты Claude Code — каноническую структуру: `cat ../../product/AGENTS.md` (правила, source в продукте), `cat ../../CLAUDE.md` (должно быть `@product/AGENTS.md` — указатель в корне), `ls -la ../../.claude/` (корень: сюда лягут скиллы/хуки-обёртки).

4. Если создавал локальный settings проекта — его тоже.

## Проверка

После выполнения проверь руками:
- На обычное чтение файлов проекта AI не спрашивает подтверждения
- На `git push` AI всё ещё запрашивает подтверждение
- В `AGENTS.md` нет инструкций «как кодить» — только индекс на правила (которые заведём позже)
- Если Claude Code: `cat ../../product/CLAUDE.md` показывает то же что `cat ../../product/AGENTS.md` (симлинк в продукте работает)
- Если Claude Code: `cat ../../CLAUDE.md` показывает `@product/AGENTS.md` (корневой указатель на правила продукта на месте)
