# Промты — продуктовая часть Урока 1

Каждый промт отвечает за свой слой работы. Они **не повторяют** друг друга, а наслаиваются. Если кажется, что промты делают одно и то же — посмотрите колонки «Что делает» и «Что НЕ делает».

Чтобы запустить промт, скажите своему AI: «прочитай `prompts/<имя>.md` и выполни» — внутри есть разводка под Claude Code / Codex / Cursor.

## Слои

| Файл | Слой | Что делает | Что НЕ делает |
|---|---|---|---|
| `01-ai-setup.md` | Настройка | Permissions AI + `AGENTS.md` как разводящий хаб | — |
| `02-product-context.md` | **Концепция** | Заполняет в `spec.md` разделы «Продукт» (что / для кого / главный сценарий / основные действия) и «Платформа» (по умолчанию web responsive). Закладывает общие edge cases (empty / error / loading на уровне продукта). | Не строит скелет экранов и не описывает отдельные экраны — это работа 03/04, потому что скелет зависит от материалов (Figma или скриншоты или ничего). |
| `03-figma-path.md` | **Скелет + детализация — ветка А (Figma)** | Через Figma MCP сканирует файл, собирает скелет состава продукта по разделам (Публичная / Кабинет / Админка), **согласовывает с пользователем** (что включаем / что не нужно / чего не хватает), записывает в `spec.md → Экраны (индекс)`. Затем раскрывает каждый согласованный экран в отдельный файл `../../product/docs/screens/<url>.md` со всеми состояниями, действиями, данными. | Не задаёт вопросы про концепцию (что за продукт, для кого) — она уже в `spec.md` после `02`. |
| `04-own-design-path.md` | **Скелет + детализация — ветка Б/В (свой дизайн или без)** | По скриншотам (Б) или через диалог по типовым разделам (В) собирает и согласовывает скелет, потом строит файлы экранов. | То же, что у `03` — не возвращается к концепции, работает только с экранами и логикой. |
| `05-prd-spec-template.md` | **Сверка + одностраничник** | Сверяет `spec.md` и `../../product/docs/screens/` с каноничной структурой, дочитывает Figma/скриншоты на предмет пропусков, генерирует `PRD.md` как одностраничную проекцию раздела «Продукт». | Не делает «продуктовую» работу заново и не описывает новые экраны — это полировка готового, не сборка. |

## Какую ветку выбрать для работы с дизайном

- **Figma есть, платный тариф** → `03-figma-path.md`
- **Дизайн в другом инструменте (Sketch / Penpot / Photoshop), наброски на бумаге, описание словами** → `04-own-design-path.md`
- **Дизайна нет, есть только идея** → `04-own-design-path.md` (в режиме «без дизайна»)

## Итоговые артефакты

- `../../product/docs/spec.md` — обзор продукта (Продукт, Платформа, Данные, Доступы, Уведомления) + индекс экранов
- `../../product/docs/screens/<url>.md` — детализация каждого экрана: доступ, layout, данные, состояния, действия, связи, валидация
- `../../product/docs/PRD.md` — одностраничник для не-технической аудитории (генерируется в `05`)

На эти артефакты опираются все последующие уроки.
