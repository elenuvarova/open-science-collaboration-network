# Аналитика — считаем посетителей и ключевые события

> **Цель:** на проде на всех страницах публичного сайта стоит счётчик, который показывает, сколько людей приходит, откуда и доходят ли до целевого действия (клик по CTA, signup). Выбор инструмента — за студентом, фиксируется в ADR.

## Зачем

Без аналитики «работает или нет» решается на ощущениях. Со счётчиком видно: сколько посетителей, с каких источников, какая доля доходит от лендинга до регистрации. Это и есть обратная связь, ради которой продукт выложен в интернет.

## Промт

```
Помоги подключить аналитику к продукту. Сначала разбери со мной три варианта с
плюсами и минусами под мою аудиторию, дай выбрать — дефолт не навязывай.

1. Яндекс.Метрика
   + Бесплатно, РФ-юрисдикция (в пару к Yandex Webmaster из 05-indexation),
     вебвизор и тепловые карты из коробки.
   - Ставит cookie → нужно уведомление о сборе данных (152-ФЗ / политика).
     Данные у Яндекса.

2. Self-host (Plausible / Umami)
   + Данные на моём VPS (в духе курса, 152-ФЗ-friendly), без кук → без
     cookie-баннера, лёгкий скрипт.
   - Надо поднять контейнер в docker-compose рядом с приложением, обновлять
     самому. Нет вебвизора.

3. Google Analytics 4
   + Глобальный стандарт, бесплатно, мощные отчёты и связь с Google Ads.
   - Данные у Google вне РФ (риск по 152-ФЗ, если в событиях есть ПДн), нужен
     cookie consent, порог входа выше.

После моего выбора:

1. СНАЧАЛА проведи меня по регистрации у провайдера — пошагово, словами: на какой
   сайт зайти, что там создать и где в итоге взять ID/код счётчика. Не предполагай,
   что аккаунт уже есть. Дай инструкцию под выбранный инструмент:

   - Яндекс.Метрика: зайти на metrika.yandex.ru под Яндекс-аккаунтом → кнопка
     «Добавить счётчик» → вписать адрес сайта (мой прод-домен) и название →
     включить Вебвизор / карты скролла и кликов → принять условия и создать →
     открыть вкладку «Счётчик» и СКОПИРОВАТЬ ВЕСЬ готовый код счётчика (блок
     `<script>…</script>` + `<noscript>`). Попроси прислать этот код целиком, а
     отдельно — номер счётчика (8 цифр): он понадобится для `.env`.

   - Google Analytics 4: зайти на analytics.google.com → «Начать» / Admin →
     создать Account, затем Property (ресурс) с часовым поясом и валютой → внутри
     создать Data Stream → Web, указать URL сайта → открыть поток → «View tag
     instructions» → вкладка «Install manually» и СКОПИРОВАТЬ ВЕСЬ готовый код
     Google tag (`<script async src=…gtag/js?id=G-…>` + блок инициализации
     `gtag`). Попроси прислать этот код целиком, а отдельно — Measurement ID вида
     `G-XXXXXXXXXX`: он понадобится для `.env`.

   - Self-host (Plausible / Umami): здесь «регистрация» — это поднять свой
     контейнер. Подними Plausible/Umami в docker-compose рядом с приложением,
     поставь за nginx на отдельный поддомен с HTTPS (напр. `stats.<домен>`),
     обнови memory/infrastructure.md. Затем открой его веб-панель → заведи
     первого пользователя (это и есть «регистрация» на своём инстансе) → «Add a
     website» по моему домену → возьми оттуда `data-domain` и адрес скрипта.

   Объясни, куда нажимать, и в конце прямо попроси: «пришли мне готовый код
   счётчика из кабинета, который надо вставить, и его номер/ID». Дождись, пока я
   пришлю и код, и ID/домен — без них дальше не иди. Если где-то застряну на сайте
   провайдера — помоги разобраться.

2. Подключи счётчик из присланного мной готового кода. Возьми мой код и подключи
   его через next/script (strategy="afterInteractive"). Числовой ID / Measurement
   ID / домен из кода НЕ хардкодь: вынеси в ../../product/.env
   (NEXT_PUBLIC_ANALYTICS_ID или аналог) и подставляй из env, значение я впишу
   сам. Для self-host скрипт указывает на адрес моего инстанса из шага 1.

   ГДЕ ставить: счётчик должен работать на ВСЕХ страницах публичного САЙТА
   (лендинг /, /privacy, /terms, /signup) и НЕ грузиться внутри сервиса за логином
   (/app). Это маркетинговая воронка сайта, а не продуктовая аналитика внутри
   приложения.
   - Сайт и сервис в одном Next.js (вариант «подстраница» из 03-app-domain): НЕ
     клади счётчик в корневой layout.tsx — он накроет и /app. Выдели публичные
     страницы в route-group `(site)` со своим layout и подключи счётчик там; у
     сервиса (`(app)` / роуты за логином) — свой layout без счётчика.
   - Сервис на отдельном поддомене (`app.<домен>`): это другой деплой, счётчик в
     layout сайта в сервис не попадёт — просто не ставь его на поддомене.

3. Заведи 2-3 ключевых события (не больше — лишние события только шумят). Все
   события — на публичном САЙТЕ, потому что счётчика внутри сервиса нет:
   - клик по основному CTA лендинга;
   - начало регистрации (открыл /signup);
   - signup завершён.
   Если главное целевое действие продукта по spec.md живёт ВНУТРИ сервиса (за
   логином) — этим счётчиком оно не считается (он на сервис не ставится). Это не
   повод тащить счётчик в сервис ради одного события: продуктовая аналитика
   внутри приложения — отдельная история вне этого задания.
   Сделай тонкую обёртку trackEvent(name) в одном месте (../../product/lib/analytics.ts) и
   вызывай её из нужных хендлеров, не раскидывая вызовы счётчика по компонентам.

4. Если выбранный инструмент ставит cookie (Я.Метрика / GA4) — добавь короткое
   уведомление о сборе данных и пункт в политике конфиденциальности (страница
   /privacy уже есть в лендинге). Для self-host без кук баннер не нужен.

5. Зафиксируй выбор как ADR в ../../product/docs/memory/decisions/ADR-XXX-analytics.md
   (что выбрали, почему, какие события считаем, что счётчик стоит только на
   публичном сайте, а не в сервисе) и добавь строку в memory/INDEX.md.

ПОКАЖИ МНЕ:
- Что выбрали и короткое сравнение (почему да/нет под мою аудиторию)
- Пошаговую инструкцию регистрации у провайдера (куда зайти, что создать, где взять готовый код и ID)
- Что ты прямо попросил у меня готовый код счётчика и дождался его перед вставкой
- Где лежит ID (../../product/.env), куда вставлен счётчик (layout публичного сайта, не сервиса) и обёртка trackEvent
- Что в реалтайме счётчик увидел мой визит на сайте (открой прод, проверь в дашборде)
```

## Edge cases

- Готовый код берём из кабинета провайдера (его и просим у пользователя), но числовой ID/Measurement ID из него всё равно выносим в `.env` — чтобы dev/prod не путались и значение не было захардкожено прямо в layout.
- Счётчик — только на публичном сайте, не внутри сервиса за логином. Это маркетинговая воронка «зашёл → CTA → signup». Действия внутри приложения (за логином) этим счётчиком не считаем; для них — отдельная продуктовая аналитика вне рамок задания.
- ID счётчика — не секрет (он всё равно виден в HTML), но всё равно держим его в `../../product/.env` (`NEXT_PUBLIC_*`), чтобы dev и prod не путались и значение не хардкодилось.
- Если в продукте есть персональные данные пользователей, в события НЕ кладём email, имя, телефон — только обезличенные идентификаторы. Иначе ПДн утекают во внешнюю аналитику (для Я.Метрики/GA это юридический риск по 152-ФЗ).
- Self-host (Plausible/Umami) — это ещё один контейнер и ещё один поддомен с HTTPS. Если не готовы поддерживать — Я.Метрика проще, данные считаются так же.
- Считать всё подряд — антипаттерн. 2-3 события, привязанные к воронке «зашёл → signup → целевое действие», дают больше, чем 50 кликов по кнопкам.
- На localhost счётчик можно не подключать или фильтровать свой трафик, иначе он засоряет статистику прода.
