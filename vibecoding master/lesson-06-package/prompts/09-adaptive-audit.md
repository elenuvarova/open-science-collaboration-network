# Финальный адаптив-аудит лендинга

## Что проверяем

Финальный прогон с фокусом на **лендинг и новые публичные страницы** этого урока
(`/`, `/privacy`, `/terms`, `/cookies`) — они только что свёрстаны и ломаются чаще
всего. Проверяем их глубоко: на 4-5 размерах экрана **и на разных соотношениях
сторон** (портрет/ландшафт). Главный критерий — **ничего не вылазит за блоки и за
край экрана** там, где это не задумано (нет горизонтального скролла, контент не
обрезан и не выходит за свой контейнер).

Остальной продукт (экраны за логином) адаптивно проверяли по ходу курса, а
функционально прогоним в Уроке 7 (`/ux-testing`). Здесь по нему — **быстрый
контрольный sweep**: не сломалось ли что-то после добавления новых публичных
страниц.

## Размеры

| Размер | Устройство | Назначение |
|---|---|---|
| 375×667 | iPhone SE | минимум mobile |
| 390×844 | iPhone 14/15 | стандарт mobile |
| 768×1024 | iPad portrait | tablet |
| 1280×800 | Macbook | desktop |
| 1920×1080 | Wide desktop | широкий экран |

## Прогон

### Шаг 1 — DevTools

В Chrome DevTools (`Cmd+Opt+I` → `Cmd+Shift+M`) проверь все размеры.

### Шаг 2 — Чек-лист

#### Лендинг + публичные страницы (основной фокус): `/`, `/privacy`, `/terms`, `/cookies`

По каждому размеру **и каждому соотношению сторон** (портрет и ландшафт):

- [ ] Ничего не вылазит за блоки и за край экрана — контент не выходит за свой контейнер/секцию (если это не задумано)
- [ ] Горизонтального скролла нет
- [ ] Hero и секции лендинга держат сетку: колонки не наезжают, отступы не схлопываются, фон не обрезает контент
- [ ] Картинки и фоновые изображения масштабируются (не растягиваются, не вылезают за viewport)
- [ ] Текст читается без зума, заголовки не разваливаются и не обрезаются
- [ ] Длинные слова / тексты переносятся, не дают горизонтальный скролл
- [ ] Кнопки и ссылки кликаются (минимум 44×44px touch target), CTA виден на первом экране
- [ ] Мобильное меню работает (бургер открывается / закрывается)
- [ ] В ландшафте на мобиле первый экран не «съедается» — Hero и CTA остаются доступны

#### Остальной продукт (быстрый sweep): Login, основной экран за логином, главный флоу

Без глубокого прохода — убеждаемся, что новые публичные страницы ничего не задели:

- [ ] Нет горизонтального скролла и явного overflow
- [ ] Меню, формы и кнопки на месте и кликаются
- [ ] Ничего очевидно не уехало после правок этого урока

### Шаг 3 — Playwright скриншоты (опционально)

Для автоматизации прогон через Playwright:

```bash
npx playwright test --headed
```

Или скрипт:

```ts
// ../../product/scripts/screenshots.ts
import { chromium } from 'playwright'

const sizes = [
  { name: 'iphone-se', w: 375, h: 667 },
  { name: 'iphone-se-landscape', w: 667, h: 375 }, // соотношение сторон: ландшафт
  { name: 'iphone-15', w: 390, h: 844 },
  { name: 'ipad', w: 768, h: 1024 },
  { name: 'ipad-landscape', w: 1024, h: 768 },
  { name: 'desktop', w: 1280, h: 800 },
  { name: 'wide', w: 1920, h: 1080 },
]

// Фокус — лендинг и публичные страницы; продукт за логином — быстрый sweep
const pages = ['/', '/privacy', '/terms', '/cookies', '/login', '/app']

;(async () => {
  const browser = await chromium.launch()
  for (const size of sizes) {
    for (const page of pages) {
      const ctx = await browser.newContext({ viewport: { width: size.w, height: size.h } })
      const p = await ctx.newPage()
      await p.goto(`http://localhost:3000${page}`)
      await p.screenshot({
        path: `../../product/docs/screenshots/adaptive/${size.name}-${page.replace('/', 'home')}.png`,
        fullPage: true,
      })
      await ctx.close()
    }
  }
  await browser.close()
})()
```

## Что часто ломается на mobile

1. **Sticky/fixed элементы** перекрывают контент при появлении клавиатуры

2. **Длинные слова** не переносятся → горизонтальный скролл

3. **`vh` единицы** криво работают на iOS (адресная строка) — используй `dvh`

4. **Hover-only** элементы не видны без hover на touch-устройствах

5. **Маленькие touch-targets** (меньше 44×44px)

## Что часто ломается на desktop

1. **Контент растягивается на весь широкий экран** → текст становится нечитаемым (нужно `max-w-7xl` контейнер)

2. **Колонки не сбалансированы**

3. **Whitespace недостаточно** на больших экранах

## После аудита

1. Покажи пользователю скриншоты лендинга и публичных страниц по каждому размеру и соотношению сторон (портрет/ландшафт), отдельно отметь места, где что-то вылазило за блоки/экран

2. Список найденных проблем + план починки (сначала лендинг и публичные страницы, потом находки из sweep продукта)

3. Поправь критичные → ещё один прогон лендинга на проблемных размерах

4. Сохрани скриншоты в `../../product/docs/screenshots/adaptive/`

5. В `spec.md` зафиксируй какие размеры поддерживаются как «первого класса»
