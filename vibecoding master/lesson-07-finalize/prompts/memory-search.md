# Промт: Поиск по памяти проекта

> **Универсальный промт.** Реализует **3-слойный progressive disclosure** — поиск с минимальным расходом токенов. В Claude Code зашит в скилл `/memory-search`.

---

## Когда применять

Когда пользователь спрашивает что-то из «истории» проекта:

- «Было ли уже X?»
- «Почему мы выбрали Y?»
- «Как мы решали Z в прошлый раз?»
- «Что делали на прошлой неделе / в этой ветке?»
- «Покажи ADR / finding по теме N»
- «Какие открытые вопросы остались с прошлой сессии?»

---

## Принцип: 3-слойная progressive disclosure

Не грузи всю память подряд — это съедает контекст. Иди слоями.

| Слой | Что делает | Когда переходить дальше | Токены |
|---|---|---|---|
| **L1 Search** | Grep по `state.md` + `memory/INDEX.md` | Если найдено ≥1 кандидата | ~50–100 |
| **L2 Fetch** | `Read` конкретного файла по ID (ADR-XXX, F-XXX, session-YYYY-MM-DD) | Если в L2 не нашлось ответа | ~500–1500 на файл |
| **L3 Timeline** | Соседние сессии вокруг даты-якоря (±N дней) | Только если запрос про широкий контекст | ~2000–5000 |

**Правило:** не переходи на следующий слой, пока не убедился, что текущего недостаточно.

---

## Параметры

- **Запрос пользователя** (что ищем): ключевые слова, тема, дата
- **Активный проект** — обычно из контекста чата (правило «один чат = один проект»). Если не ясно — спроси.

---

## Шаги промт

### Шаг 0 — Определи путь к памяти

`../../product/docs/memory/` — стандартный путь памяти проекта (создан в Шаге 0 этого урока).

Для отдельного проекта — `../../product/docs/memory/` в корне его проекта.

Если `memory/INDEX.md` нет — память живёт по старой схеме (`notes.md` + `architecture-decisions.md`). Сообщи пользователю, предложи мигрировать.

### Шаг 1 — Search (L1)

Прочитай:
- `../../product/docs/memory/state.md` (≤80 строк)
- `../../product/docs/memory/INDEX.md` (≤200 строк)

Это максимум ~250 строк суммарного контекста.

**Grep** по содержимому: ищи ключевые слова из запроса в:
- Заголовках таблиц ADR / Findings / Sessions в INDEX
- Разделе «Последние решения» в state.md
- «Активный бэклог» state.md (если запрос про текущее)

Если в запросе **дата или временное выражение** («прошлая неделя», «2026-04-10», «на этапе спек») — отфильтруй sessions по дате/имени.

**Выход шага 1:** список кандидатов, каждый — ID + file path + однострочное обоснование релевантности.

```
- ADR-006 (no-gitlab-ci) → memory/decisions/ADR-006-no-gitlab-ci.md
  Релевантно: упоминает CI/CD, отказ от GitLab Actions
- session 2026-04-15 (sidebar-unification) → memory/sessions/2026-04-15-sidebar-unification.md
  Релевантно: дата подходит под "прошлая неделя"
```

Если кандидатов **нет** — сообщи пользователю: «В памяти проекта <PROJECT> нет записей по запросу. Возможно, тема не фиксировалась, или была до миграции памяти». Не переходи на L2 «на всякий случай» — это потеря токенов.

### Шаг 2 — Fetch (L2)

Для каждого релевантного кандидата (обычно 1–3 файла) — `Read` конкретного файла.

**Не читай весь `decisions/` подряд.** Только конкретные файлы по ID из шага 1.

Извлеки релевантную часть:
- Из ADR — раздел Decision + Alternatives Considered (если запрос «почему X», «что отвергли»)
- Из Finding — само описание (короткие)
- Из Session — раздел «Что сделано» / «Принятые решения» / «Открытые вопросы»

### Шаг 3 — Timeline (L3, опционально)

Применяй **только** если:
- Запрос про широкий контекст («что происходило в апреле», «где мы были после деплоя»)
- На L2 не нашлось — нужен более широкий поиск

Возьми дату-якорь (например, дата найденной сессии или указанная пользователем) и прочитай соседние sessions ±N дней (обычно ±3–7 дней).

### Шаг 4 — Сформируй ответ

Структура:

```
## Найдено

**По запросу «<запрос>»:**

### Кандидат 1: ADR-006 — Отказ от GitLab CI
- **Дата:** 2026-04-12
- **Контекст:** ...
- **Решение:** ...
- **Альтернативы и почему отвергли:** ...
- **Подробнее:** memory/decisions/ADR-006-no-gitlab-ci.md

### Кандидат 2: Session 2026-04-15 — Унификация сайдбара
- ...

## Связанные записи

- ADR-005 (предшественник) — memory/decisions/ADR-005-...
- F-002 (про права доступа) — memory/findings/F-002-...

## Открытые вопросы (если есть в найденном)

- ...
```

Если ответ можно дать одной строкой — давай одной строкой. Не раздувай.

---

## Антипаттерны (чего не делать)

- 🔴 Прочитать все ADR / findings / sessions подряд «на всякий случай» — это потеря токенов
- 🔴 Перейти на L2 не убедившись, что в L1 нашлись релевантные кандидаты
- 🔴 Перейти на L3 без явной нужды в широком контексте
- 🔴 Цитировать целые файлы вместо извлечения релевантной части
- 🔴 Не предложить миграцию, если у проекта старая структура (`notes.md` без `memory/`)
