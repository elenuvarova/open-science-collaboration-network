# Как собрать свой промт из проделанной работы

> **Это методичка-промт.** На неё ссылаются мини-задания «оформи как свой промт». Сама по себе она не запускается.

---

## Принцип

Промт — это **переиспользуемый рецепт** того, что ты только что сделал руками. Когда видишь паттерн (типа «всегда после деплоя я прохожу 14 пунктов безопасности», «всегда после нового UI я прогоняю адаптив на трёх разрешениях») — оформляешь это в один файл, на который потом будешь ссылаться.

**Когда оформлять промт:**
- Ты только что сделал что-то по подробным инструкциям
- Понимаешь, что **в следующем проекте** или **на следующем шаге** придётся делать то же самое
- Не хочешь каждый раз переписывать или искать инструкцию

**Не оформлять промт:**
- Если задача разовая (например, миграция БД при первой настройке) — не делай
- Если шагов 2–3 — это не промт, это пара строк в чат

---

## Что входит в промт

Структура из 6 секций:

```markdown
# Промт: <название>

## Когда применять
<2–4 буллета: в каких ситуациях этот промт запускается>

## Параметры
<что AI должен знать перед началом — список>

## Шаги

1. <конкретный шаг с проверкой>

2. <следующий>
...

## Edge cases
<типичные особые ситуации и как с ними быть>

## Что должно получиться
<конкретный артефакт: файл / отчёт / изменённое состояние проекта>

## Триггеры активации (для скилла Claude Code)
<фразы на русском, по которым Claude должен распознать "это про этот промт">
```

---

## Промт «оформи как промт»

Используй этот промт после мини-задания «собери свой промт» (или в любой момент, когда видишь что нужен переиспользуемый рецепт):

```
Помоги мне оформить переиспользуемый промт на основе того, что мы только что
делали.

КОНТЕКСТ:
- Мы только что сделали: <короткое описание — что именно делал по инструкциям>
- Это паттерн, который повторится: <где ещё, в каких будущих задачах или проектах>
- Эталон-шаблон: prompts/<name>.md (если есть — используй как ОРИЕНТИР,
  не копируй буквально; адаптируй под мой стиль и контекст)

ШАГ 1 — Соберём структуру.
По 6 секциям (см. _HOW-TO-BUILD-YOUR-PROMPT.md):

1. Когда применять — спроси меня 2–4 ситуации

2. Параметры — что нужно знать перед запуском

3. Шаги — пошаговая инструкция, с проверками после каждого

4. Edge cases — что может пойти не так

5. Что должно получиться — конкретный артефакт

6. Триггеры активации — фразы по-русски, по которым Claude должен распознать,
   что нужен этот промт

По каждой секции спрашивай меня по одному вопросу за раз — не списком.
Если у эталона-шаблона есть полезный материал — показывай мне 2-3 варианта формулировки
и я выбираю / правлю.

ШАГ 2 — Сохрани в моём проекте.

Положи файл в prompts/<name>.md (имя я скажу, или предложи 2 варианта).

ШАГ 3 — Обёртка в скилл. ТОЛЬКО Claude Code.

Если ты Codex / Cursor / другой AI — ШАГ 3 ПРОПУСТИ. Готовый рецепт это
prompts/<name>.md из ШАГА 2; дальше вызывай его по пути: «прочитай
prompts/<name>.md и выполни». Обёртка и .claude/ тебе не нужны.

Если ты Claude Code — в ../../.claude/skills/<name>/SKILL.md создай обёртку:

---
name: <skill-name>
description: <одна строка — когда применять. Включи 3-5 русских триггеров для автоподхвата>
model: sonnet
---

# /<skill-name>

Обёртка над промтом `prompts/<name>.md`.

## Триггеры
- <триггер 1>
- <триггер 2>
- <триггер 3>

См. полный промт → [prompts/<name>.md](../../prompts/<name>.md)

ШАГ 4 — Тестовый прогон.

Скажи мне фразу-триггер, и я проверю что Claude Code действительно подхватил
скилл и применил промт. Если нет — поправим description / триггеры.

ШАГ 5 — Зафиксируй в памяти.

В ../../product/docs/memory/state.md в раздел «Активный бэклог» (или в «Готово») добавь строку:
"Собран свой промт /<skill-name> — детали в prompts/<name>.md".

В ../../product/docs/memory/sessions/ — этот пункт попадёт автоматически в следующий
/save-session.

ВАЖНО:
- НЕ копируй эталон-шаблон 1-в-1 — это твой промт, под твою манеру и стиль.
  Шаблон используем как референс структуры, не как готовое решение
- Минимум одна твоя правка относительно шаблона: переформулировка шага, своё
  edge case, свои триггеры. Иначе это не «твой промт», а копия
- Если шаблона нет — собирай с чистого листа на основе только что проделанного
```

## Что использовать как референс

Эталоны-шаблоны лежат рядом с этим файлом и подобными промтами:

| Эталон | Когда использовать |
|---|---|
| `new-feature.md` | Базовый, ставится сразу |
| `save-session.md` | Базовый, ставится сразу |
| `memory-search.md` | Базовый, ставится сразу |
| `ux-testing.md` | **Соберёшь сам** после шага «адаптив + состояния» в прототипе. Эталон используй как ориентир |
| `security-check.md` | **Соберёшь сам** после первого ручного аудита безопасности. Эталон используй как ориентир |
| `expert-analysis.md` | **Опционально** — соберёшь когда впервые столкнёшься со сложным архитектурным выбором. Эталон используй когда понадобится |

Эталоны — не «единственно правильное решение». Это **отправные точки**. Твой собственный промт может быть проще, или иначе формулировать триггеры, или содержать дополнительные шаги под твою специфику. Так и должно быть — это **твой стек**.

---

## Связь с финалом

На финальном этапе (сборка библиотеки модулей) ты группируешь все собранные промт по направлениям (`modules/research/`, `modules/design/`, `modules/development/`).

К этому моменту у тебя уже есть:
- 3 базовых промта (`save-session`, `memory-search`, `feature-dev`)
- 2 собранных собственных промт (`ux-testing`, `security-check`)
- Возможно `expert-analysis` если понадобился

В финале — раскладываешь это по направлениям и получаешь свой переносимый AI-стек для будущих проектов.

---

## Антипаттерны

- 🔴 **Копи-паст эталона 1-в-1.** Это не твой промт — это копия. Перепиши хотя бы один шаг своими словами и добавь свой edge case
- 🔴 **Промт на 2-3 строки.** Это не промт, это команда. Пиши только когда правда есть структура
- 🔴 **Промт без триггеров.** Скилл-обёртка без триггеров не сработает на автоподхват — Claude не поймёт «когда меня нужно вызывать». Минимум 3 фразы
- 🔴 **Промт для разовой задачи.** «Миграция БД при первой настройке» — это не повторяющийся паттерн, это разовый шаг. Не оформляй

**Куда возвращаться:** этот файл — справочник. Открывай его когда нужно собрать новый собственный промт.
