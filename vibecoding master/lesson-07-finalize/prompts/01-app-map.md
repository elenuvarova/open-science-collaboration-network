# Промт 01: Карта приложения

> **Цель:** в `../../product/docs/01-app-map.md` лежит карта всех маршрутов с ролями доступа и mermaid-диаграмма переходов, а в `../../product/docs/app-map.html` — та же карта как интерактивная страница: открываешь в браузере и наглядно видишь, из какого экрана куда можно перейти.

---

## Промт

```
Создай ../../product/docs/01-app-map.md И ../../product/docs/app-map.html (см. блок «HTML-версия» ниже) по фактическому состоянию приложения.

Прочитай:
- ../../product/development/apps/app/src/app/ (сервис) и ../../product/development/apps/landing/src/app/ (лендинг) — Next.js routing, там фактические маршруты обоих приложений
- ../../product/development/apps/app/src/middleware.ts — там логика защиты
- ../../product/docs/PRD.md — там список экранов

Сформируй:

# App Map — <project-name>

## Маршруты и доступ

| URL | Экран | Доступ | Описание |
|---|---|---|---|
| / | Главная | все | Лендинг или дашборд |
| /login | Логин | только не-авторизованный | Форма входа |
| /register | Регистрация | только не-авторизованный | Форма регистрации |
| /dashboard | Дашборд | только авторизованный | Главный экран сервиса |
| /<feature> | <Основной флоу> | только авторизованный | По PRD |
| /settings | Настройки | только авторизованный | Профиль, пароль, удаление |

(Используй РЕАЛЬНЫЕ маршруты из ../../product/development/apps/app/src/app/ и ../../product/development/apps/landing/src/app/ — не выдумывай.)

## Карта переходов (Mermaid)

```mermaid
graph LR
  Home[/] --> Login[/login]
  Home --> Register[/register]
  Login --> Dashboard[/dashboard]
  Register --> Dashboard
  Dashboard --> Feature[/<основной флоу>]
  Dashboard --> Settings[/settings]
  Settings -- "выйти" --> Home
```

(Адаптируй под реальные переходы — посмотри Header / Sidebar / какие <Link> есть.)

## UI-состояния (для каждого экрана)
- Загрузка
- Пустой
- Заполненный
- Ошибка

## Глобальные правила доступа
- Все экраны кроме /, /login, /register требуют авторизации.
- Неавторизованный → редирект на /login (через middleware).
- Авторизованный на /login или /register → редирект на /dashboard.

---

HTML-версия — ../../product/docs/app-map.html (генерируй из ТЕХ ЖЕ данных, что и .md,
одним проходом, чтобы карты не разошлись). Это самодостаточная страница, чтобы открыть
в браузере и наглядно видеть связи между экранами:
- один файл, без сборки и зависимостей: mermaid подключи через CDN
  (<script type="module"> import mermaid from "https://cdn.jsdelivr.net/npm/mermaid@11/dist/mermaid.esm.min.mjs"; mermaid.initialize({ startOnLoad: true }); </script>),
  граф отрисуется сам при открытии;
- сверху — граф переходов (тот же, что в mermaid-блоке выше): узлы = экраны (подпись:
  название + маршрут), стрелки = переходы между экранами, подписанные чем переход
  («выйти», «после логина», «открыть заказ» и т.п.);
- подсветка узлов по доступу (гость / авторизованный / админ) через classDef + легенда;
- ниже графа — таблица маршрутов и ролей (как в .md);
- заголовок страницы и дата генерации сверху.

ПОКАЖИ МНЕ:
- Финальный ../../product/docs/01-app-map.md (mermaid рисуется в Markdown Preview)
- ../../product/docs/app-map.html — открой в браузере: виден граф переходов между
  экранами с подсветкой по ролям и таблица маршрутов
```

## Edge cases

- Если в проекте есть admin-зона — добавь раздел про неё (с пометкой "появится позже")
- Если есть API без UI (вебхуки, public API) — в карте они не показаны, но упомяни в ../../product/docs/api-routes.md (опционально)
