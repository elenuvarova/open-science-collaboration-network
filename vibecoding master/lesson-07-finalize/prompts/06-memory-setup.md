# Инструкция: Заполняем память проекта

## Предусловие

Перед этим промтом должен быть запущен `setup.sh` — он создаёт скелет `.claude/`.
Проверка: `bash ../../.claude/hooks/session-start.sh` (из папки урока) выводит статус ✓.

Также нужны: `../../product/docs/spec.md` (из этапа продуктового интервью) и список ADR которые накопились за предыдущие этапы.

---

## Задача

Заполни шаблоны реальным содержимым проекта.

### Шаг 1 — Заполни `../../product/docs/memory/state.md`

Замени плейсхолдеры на актуальное:
- `<название проекта>` → реальное название
- Текущая шаг → «Защита от регрессий»
- Активный бэклог → задачи которые сейчас делаем
- Ключевые файлы → реальные пути к spec.md, DESIGN.md, UI-киту

Держи файл ≤80 строк.

### Шаг 2 — Заполни `../../product/docs/memory/project-context.md`

Из `../../product/docs/spec.md` разделы «Продукт» и «Платформа» — перенеси суть в 2–3 предложения (что за продукт, для кого / какие роли, где открывают).
Из spec.md раздел «Что НЕ делаем» — перенеси список ограничений.

### Шаг 3 — Перенеси ADR из предыдущих этапов

Создай по одному файлу на каждое архитектурное решение:

```
../../product/docs/memory/decisions/ADR-001-<slug>.md
../../product/docs/memory/decisions/ADR-002-<slug>.md
...
```

Формат каждого ADR:

```markdown
# ADR-001: <Название решения>

## Context
<Почему вообще стоял этот вопрос>

## Decision
<Что выбрали>

## Alternatives Considered
- <вариант 1>: <почему отвергли>
- <вариант 2>: <почему отвергли>

## Consequences
<Что это даёт и чего стоит>

## Status: Accepted
## Date: YYYY-MM-DD
```

Типичные ADR для продукта:
- ADR-001: выбор стека (Next.js vs другие)
- ADR-002: выбор ORM (Prisma vs Drizzle)
- ADR-003: деплой (VPS vs Vercel)
- ADR-004: архитектура UI (FSD, UI-кит, shadcn)
- ADR-005: схема авторизации (NextAuth vs custom)

Добавь только те, которые реально обсуждались в твоём проекте.

**Обязательно зафиксируй процессный ADR «spec → test → код»** (следующим свободным номером в твоём проекте) — это ключевое решение, на котором держится защита от регрессий:

```markdown
# ADR-NNN: Цепочка spec → test → код

## Context
Между сессиями AI «забывает» прошлую логику — без явной спеки он генерирует похожее,
но не идентичное поведение, и фичи незаметно дрейфуют. Регрессии возникают там, где
визуально «всё работает».

## Decision
Любое изменение поведения проходит три шага по порядку:
1. Сначала обновляем spec (`docs/screens/<screen>.md` или `docs/screens/_global.md`).
2. Потом обновляем тест-кейс (`docs/test-cases.md`) — новое ожидаемое поведение в Дано/Когда/Тогда.
3. Только потом меняем код.
Тесты — black-box: бьют по публичному интерфейсу (HTTP API, UI), не импортят внутренности,
поэтому код можно переписать, а тест-кейс не сломается.
IMPL: docs/screens
IMPL: docs/test-cases.md
IMPL: src/app/api

## Alternatives Considered
- Менять только код, без spec и тест-кейсов: классический путь к регрессиям через 5–10 фич.
- White-box тесты (импорт внутренних функций): ломаются при рефакторинге, ложные срабатывания.

## Consequences
Регрессии ловятся (spec и тест-кейс показывают, что сломалось), у AI есть «карта истины».
Цена — чуть больше шагов на простые правки и поддержание spec/test-cases в актуальности.

## Status: Accepted
## Date: YYYY-MM-DD
```

### Шаг 3.5 — Пометь ADR тегом IMPL:

После написания каждого ADR — добавь в секцию `## Decision` одну или несколько строк вида:

```markdown
IMPL: src/lib/auth.ts
IMPL: middleware.ts
```

`IMPL:` — это маркер: какой файл в кодовой базе является реализацией этого решения.

Зачем: через неделю или несколько сессий можно быстро проверить, что решение из ADR
действительно отражено в коде. Если файл удалили или переименовали — IMPL укажет куда смотреть.

Пример заполненного ADR:

```markdown
## Decision
Используем Prisma как ORM. Выбрали за типобезопасность и миграции из коробки.
IMPL: prisma/schema.prisma
IMPL: src/lib/db.ts
```

Для ADR-002 (ORM), ADR-003 (деплой), ADR-004 (UI-кит) — IMPL обязателен.
Для ADR-001 (выбор стека) — можно написать IMPL: next.config.ts или пропустить.

### Шаг 4 — Обнови `../../product/docs/memory/INDEX.md`

Для каждого созданного ADR добавь строку в таблицу:

```
| ADR-001 | <Название> | [ADR-001-<slug>.md](decisions/ADR-001-<slug>.md) |
```

### Шаг 5 — Проверка

После всех шагов покажи:

```bash
find ../../.claude -maxdepth 3 -type f | sort
```

И запусти hook:

```bash
bash ../../.claude/hooks/session-start.sh
```

Счётчик ADR должен показать ненулевое число.
