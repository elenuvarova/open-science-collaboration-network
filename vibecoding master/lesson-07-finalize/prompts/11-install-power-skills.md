# Добавляем в библиотеку шесть повседневных скиллов

Цель: в личной библиотеке появляются шесть скиллов, которые закрывают самые частые задачи на любом проекте — объяснить непонятный код, прогнать ревью, разобраться с багом по логам, почистить код после AI-сессии, разнести крупную задачу на параллельных агентов, подтянуть память проекта из транскриптов.

В курсе вы уже собрали `/security-check`, `/ux-testing`, `/save-session`, `/memory-search`. Эти шесть — следующий слой: на которые не хочется тратить токены и время в каждом новом проекте.

## Что это за скиллы

**`/code-explainer`.** Объясняет конкретный сценарий в коде. Не «опиши весь репо», а «как у меня работает регистрация», «нарисуй sequence diagram оформления заказа». На выход — таблица компонентов с ролями, пошаговый трейс «триггер → результат», mermaid-схема. Особенно полезно когда возвращаетесь к старому проекту или заходите в чужой код.

**`/code-review`.** Запускает пять параллельных сабагентов: security, бизнес-логика, производительность, архитектура, стандарты. Сводит в один отчёт с приоритетами от critical до low. Стоит прогонять перед каждым мерджем большой ветки, особенно после длинной AI-сессии — глаз замыливается, скилл подсветит всё что упустили.

**`/debug`.** Не даёт лечить баг «по интуиции». Заставляет сформулировать 3–5 конкретных гипотез («не вызывается handler», «вход в функцию пустой», «БД отдала null»), добавить точечное журналирование, попросить вас воспроизвести, прочитать логи и только потом править — причём только подтверждённую гипотезу. Гипотезы которые логи опровергли — откатываются. После фикса инструментация удаляется. Это дисциплина которая экономит часы.

**`/deslop`.** Берёт diff против main и убирает «AI-следы»: лишние объяснительные комментарии, защитные try/catch на вызовах внутренних функций, `as any` для обхода типов, стилистические несоответствия. Прогон через `/deslop` после большой AI-сессии — чистит ветку до состояния, в котором её не стыдно отдать на ревью.

**`/orchestrate-local`.** Декомпозирует крупную задачу на дерево локальных Task-агентов. Главный (planner) держит план в чате, рабочие подагенты (worker / verifier / subplanner) гоняются параллельно, общаются через структурированные handoff'ы. Не для каждой задачи, а когда реально есть несколько независимых веток — например, надо разом обновить три фичи или прогнать миграцию + обновить UI + поправить тесты.

**`/continual-learning`.** Раз в месяц или после большой сессии читает транскрипты ваших чатов (Claude Code, Codex, Cursor — поддержаны все три), вытаскивает оттуда устойчивые правила и решения, мёрджит в `AGENTS.md` и `DECISIONS.md` без дублей. Память проекта обновляется не вручную, а тем же AI, который её и наполнял.

## Куда положить

**Вариант А — оставить глобально.** Если только для себя, скиллы лежат в `~/.claude/skills/` и работают в любой папке. Ничего копировать не надо.

**Вариант B — в репо проекта.** Чтобы поехало в git и было у всей команды:

```bash
cd ../../product
mkdir -p .claude/skills
cp -R ~/.claude/skills/code-explainer .claude/skills/
cp -R ~/.claude/skills/code-review .claude/skills/
cp -R ~/.claude/skills/continual-learning .claude/skills/
cp -R ~/.claude/skills/debug .claude/skills/
cp -R ~/.claude/skills/deslop .claude/skills/
cp -R ~/.claude/skills/orchestrate-local .claude/skills/
```

**Вариант C — в свою библиотеку модулей** (если делали Шаг 6 этого урока). Кладёте в `../../modules/development/skills/` и регистрируете в `../../modules/development/AGENTS.md` в таблице скиллов.

## Регистрируем в индексе

В `../../.claude/skills/_INDEX.md` (или соответствующем `AGENTS.md` модуля) добавьте в раздел «Разработка» строки с триггерами:

```markdown
| «объясни код», «нарисуй схему flow», «sequence diagram» | `/code-explainer` |
| «сделай ревью», «проверь ветку» | `/code-review` |
| «дебажить», «не работает», «разберись с багом» | `/debug` |
| «убери AI-слоп», «почисти лишние комменты» | `/deslop` |
| «декомпозируй задачу», «параллельные агенты» | `/orchestrate-local` |
| «обнови память из чатов», «прокачай AGENTS.md» | `/continual-learning` |
```

## Проверка

Откройте новую сессию AI и наберите `/debug` или `/code-explainer`. Скилл должен подхватиться и задать первый вопрос — описание симптома (для debug) или сценария (для code-explainer). В Codex / Cursor без слэш-команд:

```
Прочитай ../../.claude/skills/code-explainer/SKILL.md и выполни.
Объясни как у меня работает <ваш критичный флоу>.
```

## Результат

В библиотеке появились шесть скиллов, доступных через `/<имя>`. В `../../.claude/skills/_INDEX.md` (или модульном `AGENTS.md`) — соответствующие строки в разделе «Разработка». Если хотите — заведите ADR в `../../product/docs/memory/decisions/` с короткой заметкой какой из шести уже пригодился в этом проекте, а какой пока ждёт случая.
