# Урок 7 — Промт 11: Прячем dev-страницы с боевого сайта

> **Цель:** витрина UI-кита `/style-guide` (и другие дев-страницы) недоступна на проде — отдаёт 404, но остаётся рабочей локально в dev. На боевом сайте по прямой ссылке её не открыть.

---

## Зачем это

`/style-guide` — это витрина компонентов из Урока 2. Она нужна вам в разработке: открыть, сверить, как выглядит кнопка или карточка. Но на боевом сайте это лишняя дверь: показывает внутреннюю кухню, путает посетителей и попадает в индекс поисковиков. В Уроке 3 мы убрали редирект главной на витрину, но сам адрес `/style-guide` всё ещё открывается по прямой ссылке. Сейчас, перед фиксацией MVP, закрываем его и для прода.

Принцип: дев-страница видна, когда `NODE_ENV !== "production"`, и отдаёт 404 на боевом. Гейт ставим на серверном слое (страница или `layout.tsx` сегмента), чтобы прод-бандл вообще не рендерил витрину.

---

## Промт

```
Закрой витрину UI-кита /style-guide (и другие dev-only страницы) на проде — пусть отдаёт 404,
но остаётся рабочей в dev. Не удаляй код витрины, только гейтим показ.

1. Найди дев-страницы: ../../product/development/apps/app/src/app/style-guide/ (App Router) или ../../product/development/apps/app/src/pages/style-guide.tsx (Pages Router),
   плюс любые showcase / playground / __dev маршруты. Покажи мне список перед правкой.

2. App Router — поставь серверный гейт. Предпочтительно отдельным layout сегмента,
   чтобы прод не рендерил содержимое вообще:

   // src/app/style-guide/layout.tsx
   import { notFound } from "next/navigation";

   export default function StyleGuideLayout({ children }: { children: React.ReactNode }) {
     if (process.env.NODE_ENV === "production") notFound();
     return children;
   }

   Если layout заводить не хочешь — тот же гейт в начале page.tsx
   (но именно на серверном компоненте, не внутри "use client").

3. Pages Router — верни 404 через getStaticProps/getServerSideProps:
   if (process.env.NODE_ENV === "production") return { notFound: true };

4. Защита в индексе: на странице витрины метатег robots noindex, nofollow
   (App Router — export const metadata = { robots: { index: false, follow: false } }).
   Убедись, что /style-guide не попал в sitemap.xml и не разрешён в robots.txt.

5. Если витрина — отдельный статический HTML (не маршрут Next) — закрой её на уровне
   сервера/прокси (Caddy/Nginx): отдавать только при dev, на проде — 404.

ПОКАЖИ МНЕ:
- Список найденных dev-страниц и какой гейт поставил на каждую
- Diff по изменённым файлам
- Как проверить: `npm run dev` → /style-guide открывается;
  `npm run build && npm start` (или NODE_ENV=production) → /style-guide отдаёт 404
```

---

## Edge cases

- **Preview / staging-окружение.** Если есть отдельный preview-деплой, где витрина нужна — гейти не по `NODE_ENV`, а по своей переменной (`SHOW_STYLE_GUIDE=true`), и держи её только в preview.
- **Витрина под авторизацией.** Альтернатива 404 — пускать на `/style-guide` только админа. Сложнее, но оставляет витрину доступной команде на проде. Для MVP обычно достаточно 404.
- **Страница уже удалена.** Если витрину снесли совсем — проверь, что не осталось битых ссылок на `/style-guide` (footer, dev-меню) и записи в sitemap.
- **Не ломай dev.** После правки обязательно проверь, что локально (`npm run dev`) витрина по-прежнему открывается — иначе потеряете рабочий инструмент сверки UI-кита.
