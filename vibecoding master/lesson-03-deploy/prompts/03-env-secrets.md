# .env, .gitignore, безопасность секретов

> **Цель:** секреты живут в `.env.local` (вне репо, права 600), есть шаблон `.env.example` для будущих переменных.

---

## Промт

```
Объясни мне коротко:
- Зачем секреты (API-ключи, пароли, токены) не должны быть в коде
- .env.local vs .env.production — разные файлы для разных окружений
- .env.example — публичный шаблон без значений, чтобы новый разработчик знал
  какие переменные нужны
- Реальная история: на GitHub боты-сканеры находят слитые AWS-ключи за минуты,
  запускают на них майнинг крипты — счёт на тысячи долларов

Затем:

1. Проверь что в ../../product/.gitignore есть:
   .env
   .env.*
   !.env.example
   (последняя строка — исключение, чтобы .env.example коммитился)

   Если чего-то нет — добавь.

2. Создай ../../product/.env.example с заглушками:

   # Auth
   NEXTAUTH_SECRET=
   NEXTAUTH_URL=http://localhost:3000

   # Database
   DATABASE_URL=

   # Дополнится позже:
   # OPENROUTER_API_KEY=
   # SMTP_HOST=
   # SMTP_USER=
   # SMTP_PASS=
   # TELEGRAM_BOT_TOKEN=

3. Создай ../../product/.env.local с пустыми значениями (если ещё нет):
   cp ../../product/.env.example ../../product/.env.local

   Установи права на чтение только владельцу:
   chmod 600 ../../product/.env.local

4. Если в коде где-то использованы секреты "in-place" (захардкожены) — найди и
   вынеси через process.env.X. Прогон:
   grep -rE 'sk-|ghp_|AKIA|gho_' ../../product/src/

5. Проверь историю Git на случай если .env уже коммитился раньше:
   git -C ../../product log --all --full-history -- .env*

   Если в истории есть файл .env с реальным содержимым — нужна чистка через
   git-filter-repo или BFG. Если нет — всё в порядке.

ПОКАЖИ МНЕ:
- Содержимое ../../product/.gitignore
- Содержимое ../../product/.env.example
- Подтверждение что ../../product/.env.local имеет права 600 (ls -l ../../product/.env.local)
```

---

## Edge cases

- Если пользователь уже коммитил `.env` с реальным секретом — **отзови этот секрет** в провайдере (Anthropic, OpenAI, и т.д.) и сгенерируй новый, и только потом чисти git-историю. Иначе боты уже могли его найти
- На macOS `chmod 600` работает напрямую. На Windows — права через NTFS, в WSL2 работает как Linux
- Если `.env.local` отсутствует — приложение упадёт на старте при попытке прочитать переменные. На этом этапе это ОК, заполним их на этапе БД и Auth
