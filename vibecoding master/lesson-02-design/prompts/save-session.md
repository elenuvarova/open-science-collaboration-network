# Сохранение прогресса в память проекта

> **Universal markdown.** Этот файл написан так, чтобы любой AI (Claude Code, Codex, Cursor) прочитал его и выполнил пошагово. Платформенных зависимостей нет.

Цель: когда завершена цельная работа (фича, законченный набор правок, этап) — зафиксировать, что сделано, какие решения приняты и где остановились, чтобы следующая сессия не начинала с нуля.

## Когда применять

- Когда сделано законченное изменение: фича, цельный набор правок, завершённый этап работы.
- После реализации значимой фичи (часто после `new-feature.md`).
- Перед длинным перерывом (день+).

**Не применять для мелких правок** (опечатка, цвет одной кнопки) — для них достаточно git-коммита.

## Параметры

Спроси у пользователя одной строкой, если не указано в запросе:

- **Slug сессии** — короткое имя файла, например `prototype-mock`, `auth-mvp`, `payments`.
- **Краткое описание** — 1–2 предложения, что делали (если ты участвовал — помнишь сам).

Дата сессии = текущая (можно `date +%Y-%m-%d`).

---

## Шаг 0 — Путь к памяти

Активный проект — из контекста разговора. Если не ясно — спроси. Память проекта живёт в `docs/memory/` внутри корня продукта. На курсе корень продукта — `../../product/`, то есть путь `../../product/docs/memory/`. (После сборки библиотеки модулей в Уроке 7 продукт переезжает в `projects/<name>/`, и память — соответственно `projects/<name>/docs/memory/`.) Если папки `memory/` ещё нет — создай её и `memory/sessions/`.

## Шаг 1 — Собери саммари сессии

Если ты участвовал в работе — собери сам:

- **Что сделано:** 3–7 пунктов главных результатов.
- **Изменённые / созданные файлы:** через `git diff --stat HEAD~N..HEAD` (N = число коммитов сессии) или `git status`, если ещё не коммитили.
- **Принятые решения:** архитектурные выборы (формат DESIGN.md, структура FSD, выбор адаптива и т.п.).
- **Находки:** неочевидное поведение, лимиты, нюансы.
- **Открытые вопросы / следующие шаги.**

Если ты не участвовал (свежий старт) — попроси пользователя описать в одном сообщении.

## Шаг 2 — Создай session-файл

Путь: `../../product/docs/memory/sessions/<YYYY-MM-DD>-<slug>.md` (после Урока 7 — `projects/<name>/docs/memory/sessions/...`). Если файл с такой датой и slug уже есть — добавь номер (`-2`).

Шаблон (заполняй только применимые разделы, пустые удаляй):

```markdown
# <YYYY-MM-DD> — <Описание сессии>

**Контекст:** <название задачи / этапа>

## Что сделано
- ...

## Изменённые файлы
<вставь вывод git diff --stat>

## Принятые решения
- <решение> — кратко почему

## Находки
- <нюанс>

## Открытые вопросы / следующие шаги
- ...

## Связанное
- Предыдущая сессия: <YYYY-MM-DD>-<slug>.md
```

## Шаг 3 — Обнови `state.md`

В `../../product/docs/memory/state.md` (после Урока 7 — `projects/<name>/docs/memory/state.md`):

- **Текущая фаза** — обнови на следующий шаг (например, «Прототип на моках работает локально → готов к деплою»).
- **Что сделано** — добавь 1–2 главных пункта.
- **Активный бэклог** — убери выполненное, добавь следующее.

Держи `state.md` коротким (≤ 80 строк): разросшиеся разделы выноси или удаляй — история всё равно в `sessions/`.

## Шаг 4 — Обнови `memory/INDEX.md`

Если файла нет — создай с таблицей «Журнал сессий». Добавь строку в начало (реверс-хронологически):

```
| YYYY-MM-DD | <задача / этап> | [<filename>](sessions/<filename>) |
```

## Шаг 5 — Покажи результат

В конце выведи пользователю: путь к созданному session-файлу, обновлённый статус из `state.md` и список открытых вопросов на следующую сессию.
