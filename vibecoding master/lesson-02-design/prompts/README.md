# Промты — этап прототипа

| Файл | Когда использовать |
|---|---|
| `00-init-development.md` | Инициализация разработки: Next.js + TypeScript + Tailwind + стартовые зависимости (cva, cn, lucide). Проект (папка + докуменация) уже создан на продуктовом этапе — здесь создаётся само приложение |
| `01-design-system.md` | DESIGN.md из Figma (режим A) или с нуля (режимы Б/В) |
| `02-ui-kit.md` | shadcn-компоненты в `shared/ui/`. В режиме A — pixel-perfect сборка по 5-шаговому workflow со сверкой скриншотов Figma vs local |
| `03-code-connect.md` | **Опциональный** — по умолчанию пропускается: перенос Figma → код делается напрямую из UI-кита на этапе экранов. Code Connect автоматизирует подстановку компонентов (MCP отдаёт готовый JSX), но требует тарифа Figma **Organization/Enterprise**. В режиме Б/В не нужен вовсе. |
| `04-fsd-architecture.md` | Структура `src/` по 6 слоям FSD |
| `05-ui-design-spec.md` | **Обязательный шаг для любого режима** — визуальный контракт **дописывается в существующие файлы** `../../product/docs/screens/<url>.md` с продуктового этапа (раздел `## Визуал`). В режиме A — через `get_design_context` + `get_screenshot` из Figma. В режимах Б/В — через структурированное интервью + универсальные дефолты на «решай сам». Один файл на экран: логика (продуктовый этап) + визуал (этот промт) вместе. |
| `06-screens.md` | **Кликабельный прототип:** генерация экранов из `../../product/docs/screens/<url>.md` (логика + визуал в одном файле) через UI-кит. **Mobile + desktop одновременно в одном компоненте**, handlers на каждом интерактивном элементе, mock-state для интерактивности данных. Режим A — компоненты из UI-кита по `## Визуал` + `get_screenshot`, сверка Figma desktop + mobile vs local (на Org/Enterprise опционально через Code Connect). Режим Б/В — Playwright прогон 375/768/1440 + extreme content |
| `07-responsive.md` | **Финальный адаптив-аудит** расширенного набора ширин (320/414/768/1024/1440/1920) + платформ-специфичный тюнинг (PWA / Telegram MiniApp / нестандартные сценарии) |
| `08-verification.md` | Grep по хардкоду + запуск dev-сервера + визуальная сверка экранов |
| `09-ux-audit.md` | UX-аудит прототипа: битые кнопки, тупики, orphan screens — последний проход по фронту перед оптимизацией и деплоем |
| `10-images.md` | sharp + автооптимизация картинок + `scripts/optimize-images.js` (git-хук авто-сжатия подключается в Уроке 3) |
| `new-feature.md` | Промт: один экран/фича через интервью → бриф → реализация → ревью. Оформляется в инструмент (Задание 6), затем им собираются все экраны (Задание 6b, автопрогон). Универсальный — работает в любом AI без `.claude/` и плагинов |
| `save-session.md` | Промт: сохранение прогресса — session-файл в `memory/sessions/`, обновление `state.md` и `INDEX.md` (после завершённой цельной работы). Универсальный |

## Предусловия

- Продуктовое интервью пройдено: `../../product/docs/spec.md` готов, `../../product/AGENTS.md` создан
- Выбран путь работы с дизайном (A — Figma / Б — свой дизайн / В — без дизайна)

## Каноничные пути

AI запускается с рабочей директорией = папка текущего урока (`lessons/lesson-02-design/`). Приложение студента лежит рядом с `lessons/` — в `product/`. Поэтому все артефакты продукта адресуются с префиксом `../../product/`:

- `../../product/docs/spec.md` — спека продукта (логика)
- `../../product/docs/DESIGN.md` — создаётся первым на этом этапе
- `../../product/docs/screens/<url>.md` — на каждый экран один файл: логика с продуктового этапа + раздел `## Визуал` дописывается в `05-ui-design-spec.md`
- `../../product/src/` — корень кода продукта
- `../../product/docs/figma-snapshots/` — скриншоты Figma для сверки (режим A)
- `../../product/docs/local-snapshots/` — скриншоты локального рендера (режим A)
- `../../product/public/assets/` — ассеты экранов (картинки, иллюстрации, иконки не из lucide)
