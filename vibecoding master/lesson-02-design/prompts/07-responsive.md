# Финальный адаптив-аудит

> ⛔ **Этот этап — только локальный запуск, без выкладки наружу.** Единственный «запуск» здесь — `npm run dev` у тебя на компьютере (это разрешено и нормально). Нельзя: разворачивать приложение на хостинг/сервер (Vercel / Netlify / Render / VPS), подключать git-remote / GitHub, делать `git push`, запускать деплой-скиллы или предлагать деплой. Если кажется, что «ничего не задеплоено» — так и задумано: публикация в интернет, git и GitHub — отдельно, в Уроке 3.

Базовая мобильная версия каждого экрана уже собрана на Задании 6 одновременно с desktop (`06-screens.md` — Главное правило 3, дисциплина `prototype-interactivity.md`). Этот шаг делает три вещи поверх неё:

1. **Расширенный адаптив-аудит** — полный прогон всех экранов на широком наборе ширин (включая редкие — 320 px маленький iPhone SE, 1920 px wide-screen)

2. **Нестандартные сценарии адаптации** — сложные таблицы, многоуровневые меню, hover-only действия

3. **Прогон с extreme content на mobile** — кейсы, которые ломаются именно на узком вьюпорте и незаметны на десктопе

Если Задание 6b прошло чисто на 375/768/1440 — этот шаг **становится коротким**: только финальный прогон расширенного набора ширин.

## Шаг 1 — Расширенный прогон через Playwright MCP

> **Не Claude Code (нет Playwright MCP)?** Используй тот же Playwright, но скриптом: попроси AI написать короткий скрипт (открыть страницу → выставить нужный viewport → скриншот в `../../product/docs/local-snapshots/`), запустить через `npx playwright`, и прочитать скриншоты глазами. Результат тот же — просто командой, а не живым управлением браузером. В Cursor Playwright MCP можно подключить как в Claude Code.

Прогон всех страниц на расширенном наборе ширин (Задание 6b проверило 375/768/1440, здесь добавляем края диапазона):

```
browser_resize(320, 800)   → browser_take_screenshot   # iPhone SE — самый узкий
browser_resize(414, 896)   → browser_take_screenshot   # iPhone 11 Pro Max
browser_resize(1024, 768)  → browser_take_screenshot   # iPad Pro / маленький Desktop
browser_resize(1920, 1080) → browser_take_screenshot   # Wide-screen
```

Чек-лист на каждой ширине × каждой странице:

- [ ] Никакой горизонтальный скролл
- [ ] Никакой текст / контент не вылезает за пределы контейнера
- [ ] Все интерактивные элементы остаются нажимаемыми (не перекрыты sticky-элементами)
- [ ] Картинки масштабируются пропорционально, не растягиваются
- [ ] На 320 px tap-таргеты сохраняют ≥ 44×44 px
- [ ] На 1920 px контент не «теряется» в гигантском пустом пространстве (есть max-width или fluid scaling)

Где что-то ломается — фикс в компоненте, не локальный override на странице.

## Шаг 2 — Нестандартные сценарии адаптации

Эти кейсы часто пропускаются в базовой адаптации. Пройди по списку, проверь каждый применимый.

| Сценарий | Mobile-решение |
|---|---|
| Многоуровневое меню (sidebar с вложенностью 2+) | Accordion / drawer с back-button / sheet |
| Большие таблицы (10+ колонок) | Горизонтальный скролл / карточки на mobile / приоритизация колонок |
| Сложные модалы (multi-step, длинная форма) | Full-screen / bottom-sheet / отдельные экраны через wizard |
| Hover-only действия (kebab-menu, action-on-hover) | Всегда видны / kebab-меню / swipe-actions |
| Drag-and-drop | Long-press + контекстное меню / стрелки переноса |
| Сложные графики / charts | Упрощённая версия / только summary на mobile |
| Tooltip с важной информацией | Перенести в видимый текст (на mobile нет hover) |

Если экран попадает в один из сценариев и базовое решение не подходит — спроси пользователя, добавь решение в файл этого экрана `../../product/docs/screens/<url>.md` (раздел про адаптив).

## Шаг 3 — Прогон с extreme content на mobile

Задание 6b уже прогнало extreme content на 1440 px (короткое/длинное имя, список 1/100, пустой список, длинный email в форме). Здесь **не повторяем** эти кейсы — они уже починены. Здесь проверяем то, что ломается **именно из-за узкого вьюпорта** и на десктопе незаметно. Прогон на 375 px:

- **Неразрывные длинные строки в тексте** (URL, токен, `@username`, хештег, email прямо в контенте, а не в форме) — переносятся через `overflow-wrap: break-word`, не дают горизонтальный скролл
- **Длинные подписи кнопок/CTA** («Записаться на консультацию») — переносятся аккуратно или ужимаются, не вылезают за блок
- **Ряд чипов / тегов / фильтров** — корректно сворачивается (wrap в ряды или горизонтальный скролл-контейнер), не ломает layout
- **Длинные слова в заголовках** — заголовок переносится, не обрезается криво и не вызывает скролл
- **Большие форматированные числа / цены** («1 234 567 ₽») в узкой колонке или карточке — помещаются, не выезжают
- **Счётчики и бейджи** («99+», длинные значения в кружке) — не распирают контейнер
- **Табы и хлебные крошки** (много табов / длинные сегменты) — горизонтальный overflow решён через scroll-tabs или свёртку, нет обрезки «в никуда»
- **Пары label + value** в две колонки — на узком не сталкиваются (переход в одну колонку или перенос значения)
- **Длинные пункты в `<Select>` / dropdown** — текст опции не вылезает за край экрана, переносится или обрезается с ellipsis внутри своей ширины
- **Статус-pill с длинным текстом** («В ожидании подтверждения оплаты») — не распирает строку, переносится или ужимается, иконка не отрывается от текста
- **Toast / snackbar / alert-баннер** с длинным текстом + кнопкой действия — на 375 px текст и кнопка не наезжают друг на друга, баннер не вылезает за вьюпорт
- **Строка списка целиком** (аватар + длинное имя + мета + кнопка действия в один ряд) — на узком элементы не сталкиваются, действие остаётся доступным
- **Картинки экстремальных пропорций** — широкая панорама и высокий портрет в одном слоте: обе помещаются (object-fit / max-height), не растягивают карточку и не дают скролл
- **Код-блок / preformatted / моноширинный текст** — получает собственный горизонтальный скролл внутри блока, а не растягивает всю страницу
- **Длинный placeholder и длинное value в `<Input>`** — обрезаются с ellipsis в пределах поля, поле не расширяется за контейнер
- **Локализованные даты, время, единицы** («29 мая 2026 г., 14:30», «1 234 567 ₽», «−12,5 %») — длинные форматы помещаются в свои слоты, не ломают выравнивание
- **Граничные значения данных** — `0`, отрицательное число, прочерк «—» вместо значения: отображаются осмысленно, не «пустым местом» и не сломанной вёрсткой

Где что-то ломается — фикс в компоненте, не локальный override на странице.
